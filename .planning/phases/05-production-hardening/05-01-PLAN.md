<task type="auto">
  <name>Task 1: Add API rate limiting</name>
  <files>app.py, config.py</files>
  <read_first>
    - app.py (main routes and request handling)
    - config.py
  </read_first>
  <action>
    Implement basic API rate limiting:

1. **Add rate limit configuration** to config.py:
   - RATE_LIMIT_REQUESTS = 10 (requests per window)
   - RATE_LIMIT_WINDOW = 60 (seconds)
   - RATE_LIMIT_ENABLED = True

2. **Implement in-memory rate limiter**:
   - Track requests per IP/client using a dict with timestamps
   - Use a sliding window algorithm
   - Return 429 Too Many Requests when exceeded

3. **Apply to /api/generate endpoint**:
   - Rate limit new animation requests
   - Don't rate limit /status, /health, /stats

4. **Return proper error response**:
   - 429 status code
   - JSON error message with retry-after hint
   - Log rate limit events (without exposing internals)

Keep it simple: no Redis dependency, in-memory is fine for single-instance.
  </action>
  <acceptance_criteria>
    - /api/generate returns 429 after rate limit exceeded
    - Rate limit uses sliding window algorithm
    - Configurable via config.py
    - Does not affect /status, /health, /stats
  </acceptance_criteria>
  <verify>
    <automated>grep "rate_limit\|429\|Too Many" app.py | head -5</automated>
  </verify>
  <done>API rate limiting prevents abuse</done>
</task>

<task type="auto">
  <name>Task 3: Add batch processing endpoint</name>
  <files>app.py</files>
  <read_first>
    - app.py (existing /api/generate endpoint)
  </read_first>
  <action>
    Add batch processing for multiple animation requests:

1. **Create /api/batch endpoint**:
   - Accept array of prompts
   - Return array of job_ids
   - Process animations sequentially (not parallel to avoid load)

2. **Request format**:
   ```json
   {
     "prompts": [
       {"prompt": "Explain calculus"},
       {"prompt": "Show binary search"}
     ],
     "voiceover": false
   }
   ```

3. **Response format**:
   ```json
   {
     "batch_id": "abc123",
     "jobs": [
       {"prompt": "Explain calculus", "job_id": "xxx"},
       {"prompt": "Show binary search", "job_id": "yyy"}
     ]
   }
   ```

4. **Status tracking**:
   - Each job tracked normally via /status/<job_id>
   - Batch status can be polled by checking each job individually

5. **Implementation notes**:
   - Use existing generate_and_validate_code pipeline
   - Don't run renders in parallel for batch (resource management)
   - Return job_ids immediately, renders happen async
  </action>
  <acceptance_criteria>
    - POST /api/batch accepts array of prompts
    - Returns job_ids for each prompt
    - Each job processable via /status/<job_id>
    - Works with voiceover option
  </acceptance_criteria>
  <verify>
    <automated>grep "batch" app.py | head -5</automated>
  </verify>
  <done>Batch processing endpoint for multiple animations</done>
